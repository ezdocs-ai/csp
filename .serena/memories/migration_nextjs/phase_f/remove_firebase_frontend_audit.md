# Phase F — Remove Firebase from Next.js frontend (READ-ONLY AUDIT)

Scope: `csp/frontend-next/**` and `csp/.github/**`. Goal: zero Firebase integration while keeping Google GIS auth (`google-auth-library` + `jose`). Audit date: 2026-07-29.

## Headline
- No `firebase` / `firebase-admin` npm dependency in `frontend-next/package.json`. Auth stack is pure GIS (`google-auth-library@^10`, `jose@^6`) — KEEP.
- No Firebase refs anywhere under `csp/.github/**` (workflows, templates). CI is Cloud Build + Cloud Run only.
- Firebase surface is limited to: 1 canary deploy script + its config pair + 1 gitignore line + 2 host-allowlist patterns (defaults) + incidental text in generated API types + 1 comment.

## Files to REMOVE (runtime / deploy coupling)
| File | Why | Class |
|------|-----|-------|
| `frontend-next/firebase.json` | Firebase Hosting config: site, public dir, rewrites to Cloud Run, headers. Entire file is Firebase Hosting manifest. | runtime config |
| `frontend-next/.firebaserc` | Firebase project alias (`PROJECT_ID_PLACEHOLDER`). Only consumed by firebase-canary.ts. | runtime config |
| `frontend-next/scripts/firebase-canary.ts` | 202-line canary script: validates + token-resolves `firebase.json`/`.firebaserc`. No deploy, but exists solely to produce Firebase Hosting config. Self-contained, no other importer. | deploy tooling |

## GIS auth — explicitly PRESERVE
- `google-auth-library` (used for GIS ID-token verification server-side).
- `jose` (JWT session signing).
- No `firebase-admin` anywhere. Migration target already satisfied on the auth axis.

## Net change footprint
3 file deletions + 4 file edits (1 ignore rule, 1 host default + comment, 1 test, 1 inline comment). Zero dependency removals. Zero workflow changes. Zero cloudbuild changes. Generated `openapi.json`/`types.ts` Firestore string is out of scope (backend-owned).

## Risk
Low. Removing `firebase.json`/`.firebaserc`/`firebase-canary.ts` only disables an optional canary-hosting deploy path; primary deploy is `cloudbuild.yaml` → Cloud Run, unaffected. Host-allowlist edit is the only runtime-behavior touch and only tightens default trusted hosts — operators relying on `*.web.app` must set `ALLOWED_HOSTS` explicitly (already documented expectation in `hosts.ts` L29-30).
